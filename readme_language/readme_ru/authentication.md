# Аутентификация и безопасность

В этой системе используется строгий механизм подписи запросов для обеспечения безопасности данных между продавцом и платформой. Процесс связи включает подписи MD5 и проверку подписей RSA.

## 1. Генерация пары ключей RSA

Продавцы должны сгенерировать собственную пару ключей RSA, использовать закрытый ключ для подписи запросов и отправить открытый ключ на платформу.

### 1.1 Генерация пары ключей с помощью OpenSSL

Выполните следующие команды в Mac, Linux или Git Bash/WSL/Cygwin:

```bash
# Сгенерировать 2048-битный закрытый ключ
openssl genrsa -out rsa_private_key.pem 2048

# Сгенерировать открытый ключ из закрытого ключа
openssl rsa -in rsa_private_key.pem -out rsa_public_key.pem -pubout
```

### 1.2 Извлечение строк ключей

Из сгенерированного открытого ключа необходимо удалить строки `-----BEGIN PUBLIC KEY-----` / `-----END PUBLIC KEY-----` и символы новой строки, а затем преобразовать его в однострочную строку перед отправкой на платформу.

**Извлечение в Mac/Linux/Git Bash:**

```bash
# Извлечь строку закрытого ключа
grep -v '^-----' rsa_private_key.pem | tr -d '\n'; echo

# Извлечь строку открытого ключа
grep -v '^-----' rsa_public_key.pem | tr -d '\n'; echo
```

**Извлечение в Windows PowerShell:**

```powershell
# Извлечь закрытый ключ
Write-Output ((Get-Content rsa_private_key.pem | Where-Object {$_ -notmatch "^-----"}) -join "")

# Извлечь открытый ключ
Write-Output ((Get-Content rsa_public_key.pem | Where-Object {$_ -notmatch "^-----"}) -join "")
```

> **⚠️ Предупреждение:** Извлеченный закрытый ключ должен надежно храниться на вашем локальном сервере (в поле `RsaPrivateKey` файла `config.yaml`), и **ни в коем случае не должен быть скомпрометирован**.

## 2. Определение заголовков проверки

При выполнении HTTP-запроса в заголовок должны быть включены следующие параметры аутентификации:

| Имя параметра | Ограничение | Пример | Описание |
| :--- | :--- | :--- | :--- |
| `key` | Длина: 64 | `vratson2i5hjxgkd` | Ключ API, назначенный платформой после регистрации продавца |
| `timestamp` | Длина: 32 | `1725076567682` | Метка времени запроса (Единица измерения: миллисекунды) |
| `sign` | Длина: 32 | `0592dc64d480fb119d1e07ce0601db` | Подпись, сгенерированная с использованием алгоритма MD5 на основе содержимого запроса |
| `clientSign` | Длина: 512 | `9e0ccfe3915e94bcc5bfbBsC...` | Подпись, сгенерированная с использованием закрытого ключа RSA продавца на основе содержимого запроса |

## 3. Подробный алгоритм подписи

SDK автоматически обрабатывает всю логику подписи внутри. Если вам нужно самостоятельно разработать версию на другом языке или понять основные принципы создания подписи, обратитесь к следующим инструкциям.

### 3.1 Правила для поля `sign` (подпись MD5)

1. Получите `Secret` платформы.
2. Отсортируйте тело JSON запроса в возрастающем порядке ASCII по ключам и объедините его в строку формата `key1=value1&key2=value2...`, обозначенную как `dataStr`.
3. Получите текущую метку времени (в миллисекундах).
4. Соедините открытый текст для шифрования: `strToHash = Secret + dataStr + timestamp`.
5. Выполните шифрование MD5 для `strToHash`, и сгенерированный результат будет `sign`.

### 3.2 Правила для поля `clientSign` (подпись RSA)

1. Отсортируйте параметры запроса в возрастающем порядке ASCII по ключам.
2. Соедините все значения массива, используя символ `&`, например:
   `address=0x038B8...&amount=10.001&coin=eth&trade_id=2022013101`
3. Используйте закрытый ключ RSA продавца для выполнения подписи `RSA-MD5` для этой объединенной строки. Сгенерированный результат — `clientSign`.

## 4. Проверка подписи ответа платформы

Данные, возвращаемые платформой, также будут содержать поле `sign`, которое является результатом шифрования данных ответа платформой с использованием ее закрытого ключа RSA.

После получения ответа продавец должен использовать `PlatformPubKey` (открытый ключ платформы) из `config.yaml` для проверки этой подписи, чтобы убедиться, что данные не были подделаны.

> **💡 Подсказка:** PHP SDK предоставляет метод `verifyRsaSignature($data)`, который позволяет разработчикам быстро проверить данные, возвращенные платформой.
