## 1. Global Public Information

All JSON response data returned by the platform follows this public structure:

| Field Name | Type | Example | Description |
| :--- | :--- | :--- | :--- |
| `code` | integer | `1` | Global status code. `1` represents success, `0` or `-1` represents failure |
| `msg` | string | `ok` | Returned text description |
| `data` | object | `{"OpenId":"PT00001"}` | Specific data content returned, varying by API |
| `timestamp` | string | `"1725439986754"` | UTC Timestamp (milliseconds) |
| `sign` | string | `9e0ccfe3915e...` | Signature generated by the platform using its RSA private key on the response data |

## 2. Create New User (create_user)

### API Description
Creates a new platform user, requiring the user's unique ID, which is the UserOpenId.

### HTTP Request
* **URL:** `https://sandbox-api.privatex.io/sdk/user/create`
* **Method:** `POST`

### Request Parameters
| Parameter Name | Required | Type | Description |
| :--- | :--- | :--- | :--- |
| `OpenId` | Yes | string | It is recommended to use the platform standard prefix + the user's unique ID to form the OpenId. |

### Response Parameters
*(Includes Global Information)*
| Parameter Name | Type | Description |
| :--- | :--- | :--- |
| `data.OpenId` | string | User's unique OpenId |

### Example Code (cURL)
```bash
curl --location 'https://sandbox-api.privatex.io/sdk/user/create' \
--header 'key: vratson2i5hjxgkd' \
--header 'sign: 0592dc64d480fb119d1e07ce06011db8' \
--header 'clientSign: xxxxxxxxxxxxxxxxx' \
--header 'Content-Type: application/json' \
--header 'timestamp: 1725076567682' \
--data '{ 
  "OpenId":"PT00001"
}'
```

## 5. User Withdrawal (withdraw)

### API Description
Initiates a withdrawal operation, transferring funds from the partner's fund pool to the address specified by the user.

> **⚠️ Warning:**
> * Once a transaction is initiated on the blockchain network, it **cannot be reversed or refunded**. Please ensure proper risk control checks before calling this API.
> * You must ensure that the withdrawal pool has a sufficient balance of the token and Gas fees (such as ETH/TRX).

### Business Logic
1. A unique order number from the business platform is usually used as `SafeCheckCode` to prevent duplicate withdrawals.
2. The transaction is matched against the platform's risk control rules:
   * **Auto-approved:** It goes directly on-chain, and `data` will return the transaction hash.
   * **Secondary Review (`code=2`):** Requires manual review by an administrator on the channel platform. Once reviewed, the status will be notified asynchronously via Webhook.

### HTTP Request
* **URL:** `https://sandbox-api.privatex.io/sdk/partner/UserWithdrawByOpenID`
* **Method:** `POST`

### Request Parameters
| Parameter Name | Required | Type | Description |
| :--- | :--- | :--- | :--- |
| `OpenId` | Yes | string | User's unique OpenId |
| `TokenId` | Yes | string | Token ID (See Appendix)|
| `Amount` | Yes | float | Withdrawal amount |
| `AddressTo` | Yes | string | Target withdrawal address |
| `CallBackUrl` | No | string | Status change callback URL |
| `SafeCheckCode` | No | string | Security verification code (Business Order ID) |

### Response Status Code Description
| `code` | Description |
| :--- | :--- |
| `1` | Transaction successful and submitted on-chain, `data` returns the hash. |
| `2` | Transaction submitted, but triggered platform risk control, requiring secondary review. |
| `0` or `-1` | Parameter error, insufficient balance, or transaction failed. Check `msg` for details. |

### Example Code (cURL)
```bash
curl --location 'https://sandbox-api.privatex.io/sdk/partner/UserWithdrawByOpenID' \
--header 'key: vratson2i5hjxgkd' \
--header 'sign: 0592dc64d480fb119d1e07ce06011db8' \
--header 'clientSign: xxxxxxxxxxxxxxxxx' \
--header 'Content-Type: application/json' \
--header 'timestamp: 1725076567682' \
--data '{ 
  "OpenId": "PT00001", 
  "TokenId": "4", 
  "Amount": "0.02", 
  "AddressTo": "TQdL5yttJPTx7hJmBhGfo2LcE7AXLPtHSg", 
  "CallBackUrl": "http://xxxxxx/withdraw_callback", 
  "SafeCheckCode": "1000000000000000"
}'
```

## 6. Withdrawal Order Secondary Review (Webhook)

### Callback Description
When an administrator configures a "Risk Control Callback URL" in the merchant backend, the platform will actively initiate an HTTP request to this URL when processing a withdrawal transaction to ask the merchant's business end whether to release the withdrawal.
**The platform will only release the funds if the merchant API returns `code=0`.**

> **⚠️ Note:** The platform will assign an independent **Risk Control RSA Public Key (`PlatformRiskPubKey`)** to the merchant. The merchant must use this public key to verify the authenticity of the signature for this callback.

### HTTP Request Initiated by Platform
* **Method:** `POST`
* **URL:** Merchant's configured Webhook URL `/withdrawal/order/check`

### Callback Parameters
| Parameter Name | Required | Type | Description |
| :--- | :--- | :--- | :--- |
| `safeCode` | No | string | The merchant's submitted withdrawal order ID (`SafeCheckCode`) |
| `openId` | Yes | string | Withdrawing User's ID |
| `tokenId` | Yes | string | Token ID |
| `toAddress` | Yes | string | Withdrawal Target Address |
| `amount` | Yes | string | Withdrawal Amount |
| `timestamp` | Yes | int | Millisecond timestamp |
| `sign` | Yes | string | Signature generated by the platform using its risk control private key |

### Expected Response from Merchant
After processing, the merchant API must return the following JSON:

| Parameter Name | Type | Description |
| :--- | :--- | :--- |
| `code` | int | Verification result. `0` means agreeing to release; other numbers mean rejecting. |
| `timestamp` | int | Current timestamp in seconds |
| `message` | string | Custom description |
| `sign` | string | Merchant signs the response data using their own RSA private key |

## 7. Deposit and Withdrawal Callback Notification (Webhook)

### Callback Description
The platform pushes asynchronous notifications of token transaction status (withdrawal success/failure or user deposit credit) to the business end.

1. **Retry Mechanism:** The business end must respond with return code `0` to be considered successfully received. Otherwise, the platform will continuously retry pushing according to the strategy (initially 50 times every 2 seconds, then once every 10 minutes).
2. **Status Override:** A transaction may trigger multiple notifications. Please rely on the latest status.
3. **Failure Handling:** If the withdrawal callback `status = -1`, after the administrator resubmits the transaction in the backend, the system will push a new status notification again.

### HTTP Request Initiated by Platform
* **Method:** `POST`
* **URL:** The callback URL provided by the merchant to the service provider.

### Callback Parameters
| Parameter Name | Required | Type | Description |
| :--- | :--- | :--- | :--- |
| `type` | Yes | int | Business Type: `1` for deposit; `2` for withdrawal. |
| `status` | Yes | int | Transaction Status:<br/> `1`: On-chain successful, can be queried via hash.<br/> `-1`: On-chain failed, processable in the backend.<br/> `2`: Triggered risk control, requires manual review in admin backend.<br/> `-2`: Withdrawal application rejected by merchant risk control API. |
| `openid` | Yes | string | Channel User's Unique ID |
| `totalvalue` | Yes | string | Equivalent USDT value calculated based on market price at transaction time |
| `hash` | Yes | string | On-chain Transaction Hash |
| `confirm` | Yes | int | On-chain Confirmation Count |
| `from` | Yes | string | Transaction Initiator Address |
| `to` | Yes | string | Transaction Receiving Address |
| `amount` | Yes | string | Transaction Amount |
| `chainid` | Yes | string | Chain ID |
| `tokenid` | Yes | string | Token ID |
| `tokenaddress` | Yes | string | Smart Contract Address |
| `safecode` | No | string | Withdrawal Order Security Verification Code (OrderID) |
| `createdtime` | Yes | string | Transaction Creation Time |
| `timestamp` | Yes | string | Push Timestamp |

### Expected Response from Merchant
If received successfully, please return a JSON response body containing `{"code": 0}`.

## 8. Create Cashier Order (new_order)

### API Description
This interface is used by merchants to initiate payment or recharge requests. The system will return a payment address (Cashier URL), and users can visit this address to complete the payment.

### HTTP Request
* **URL:** `https://sandbox-api.privatex.io/sdk/api/v2/exchange/cashier/newOrder`
* **Method:** `POST`

### Request Parameters
| Parameter Name | Required | Type | Description |
| :--- | :--- | :--- | :--- |
| `outOrderNo` | Yes | string | Merchant Order ID |
| `tokenId` | Yes | int | Token ID |
| `quantity` | Yes | float | Payment Amount |
| `notifyUrl` | No | string | Callback notification URL after successful payment |

### Response Parameters
*(Includes Global Information)*
| Parameter Name | Type | Description |
| :--- | :--- | :--- |
| `data.orderNo` | string | Platform-generated Order ID |
| `data.outOrderNo` | string | Merchant Order ID |
| `data.outUserId` | string | User ID |
| `data.tokenId` | int | Token ID |
| `data.quantity` | string | Order Amount |
| `data.amount` | string | Payment Amount |
| `data.amountUsdt` | string | Equivalent USDT Amount |
| `data.network` | string | Network Name |
| `data.symbol` | string | Token Symbol |
| `data.payUrl` | string | **Cashier Payment Link**, guide the user to visit this URL |

### Example Code (cURL)
```bash
curl --location 'https://sandbox-api.privatex.io/sdk/api/v2/exchange/cashier/newOrder' \
--header 'key: vratson2i5hjxgkd' \
--header 'sign: 0592dc64d480fb119d1e07ce06011db8' \
--header 'clientSign: xxxxxxxxxxxxxxxxx' \
--header 'Content-Type: application/json' \
--header 'timestamp: 1725076567682' \
--data '{
    "outOrderNo": "order_123456",
    "tokenId": 4,
    "quantity": 100.5,
    "notifyUrl": "https://your-domain.com/callback"
}'
```

## 10. Query Wallet Balance (getWalletBalance)

### API Description
Query the token or coin balance for a specified wallet address on a given blockchain network.

### HTTP Request
* **URL:** `https://sandbox-api.privatex.io/sdk/wallet/balance`
* **Method:** `POST`

### Request Parameters
| Parameter Name | Required | Type | Description |
| :--- | :--- | :--- | :--- |
| `address` | Yes | string | Wallet address |
| `contractAddress` | Yes | string | Contract address or token symbol (e.g., `"XRP"`, `"USDT"`) |
| `chainId` | Yes | integer | Chain ID (e.g., `5` for XRP, `1` for Ethereum, `56` for BNB Chain) |

### Response Parameters
*(Includes Global Information)*
| Parameter Name | Type | Description |
| :--- | :--- | :--- |
| `code` | integer | Global status code (`1` for success) |
| `msg` | string | Status description |
| `data` | string | Token / coin balance amount (in minimal units) |
| `timestamp` | string | Response timestamp (milliseconds) |
| `sign` | string | Platform signature |

### Example Code (cURL)
```bash
curl --location --request POST 'https://sandbox-api.privatex.io/sdk/wallet/balance' \
--header 'key: your_api_key' \
--header 'sign: your_md5_sign' \
--header 'Content-Type: application/json' \
--header 'timestamp: 1725076567682' \
--data-raw '{
  "address":"rXXXXXXXXXXXXXXXXXXXXXXXXXXXX",
  "contractAddress":"XRP",
  "chainId":5
}'
```

### Response Example
```json
{
  "sign" : "",
  "timestamp" : "1725432397796",
  "data" : "1979984",
  "msg" : "ok",
  "code" : 1
}
```
